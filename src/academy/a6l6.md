## Pourquoi cet atelier

Tu as construit ta première automatisation dans n8n : chaque demande de devis arrive toute seule dans un tableau. Ici, on construit **exactement la même chose dans Make**, la plateforme la plus utilisée par les petites entreprises en France, avec une offre gratuite pour démarrer.

L'objectif n'est pas de tout refaire deux fois : c'est de te montrer que **les notions sont les mêmes partout** (déclencheur, module, mapping, filtre, planification). Une fois que tu les as comprises, tu passes d'un outil à l'autre en quelques minutes.

> **À propos des captures** : Make s'affiche en anglais. Sur certaines captures, le navigateur a traduit l'interface en français (« Magasin de données » pour *Data store*, « Exécuter une fois » pour *Run once*). Les noms anglais sont indiqués dans le texte. Si ton navigateur propose de traduire Make, **refuse** : la traduction automatique peut perturber la saisie dans l'éditeur.

## Ce que tu vas construire

**Webhook (le formulaire envoie la demande) → Filtre « E-mail renseigné » → Data store « Demandes de devis »**

![1 · Le scénario terminé : le webhook, le filtre posé sur la liaison, et l'enregistrement dans le Data store. Les coches vertes indiquent que le test a réussi](/formation/captures/mk-19-filtre-pose.webp)

| Notion | Dans n8n (atelier précédent) | Dans Make |
|---|---|---|
| L'automatisation | Workflow | **Scénario** |
| Une étape | Nœud | **Module** (un rond) |
| Le déclencheur | Form Trigger | **Webhooks › Custom webhook** |
| Le tableau intégré | Data table | **Data store** |
| Insérer une donnée | Expression `{{ $json.Prénom }}` | **Pastille** `1. prénom` |
| Tester | Execute workflow | **Run once** |

## Étape 1 · Créer un scénario

Crée un compte sur Make (l'offre gratuite suffit pour cet atelier), puis clique sur **Create scenario** (Créer un scénario).

![2 · L'accueil de Make : « Create scenario » pour partir de zéro. Le champ en haut permet aussi de décrire ton automatisation à l'assistant Maia](/formation/captures/mk-01-accueil.webp)

Le canevas s'ouvre avec un grand **+** au centre : c'est l'emplacement du premier module, le déclencheur.

![3 · Un scénario vide : clique sur le grand + pour choisir le déclencheur](/formation/captures/mk-02-nouveau-scenario.webp)

## Étape 2 · Le déclencheur : un webhook

Un **webhook** est une adresse web unique qui attend des données. Ton formulaire (Tally, Typeform, Jotform, Webflow, WordPress avec une extension, ou un formulaire Make) y envoie chaque nouvelle demande, et le scénario démarre instantanément.

1. Cherche **Webhooks** et choisis **Custom webhook** (Webhook personnalisé), marqué *Instant*.

![4 · Dans Webhooks, choisis « Custom webhook » : le scénario démarrera dès qu'une donnée arrive](/formation/captures/mk-04-webhook-perso.webp)

2. Clique sur **Create a webhook** (Créer un webhook) et donne-lui un nom clair : « Formulaire de devis ».

![5 · Nomme le webhook. L'option « Clés API » permet de le protéger : seules les requêtes qui présentent la clé seront acceptées](/formation/captures/mk-06-nom-webhook.webp)

3. Make affiche l'**adresse du webhook** et se met en écoute. Copie cette adresse et colle-la dans les réglages de ton formulaire (rubrique « Webhook » ou « Intégrations »).

![6 · Make attend une première demande pour apprendre la structure des données. Copie l'adresse avec le bouton à droite](/formation/captures/mk-07-url-webhook.webp)

4. Envoie **une demande de test** depuis ton formulaire. Make détecte alors les champs reçus.

![7 · « 7 valeurs détectées » : prénom, nom, e-mail, entreprise, besoin, budget, message. Ces champs deviennent utilisables dans la suite du scénario](/formation/captures/mk-08-donnees-detectees.webp)

> **Sécurité** : l'adresse d'un webhook est comme une clé. Ne la publie pas dans une page web visible et active les **clés API** si ton formulaire le permet.

## Étape 3 · Préparer le Data store

Le **Data store** est un petit tableau intégré à Make (comme les Data tables de n8n). Pour un usage réel, tu peux aussi choisir **Google Sheets** ou **Airtable** : la logique est identique.

1. Clique sur le **+** à droite du webhook, puis **Add module**.

![8 · Le + à droite d'un module : « Add module » pour ajouter l'étape suivante, « Add AI module » pour une étape d'IA](/formation/captures/mk-09-ajouter-module.webp)

2. Cherche **Data store** et choisis **Add/replace a record** (Ajouter/remplacer un enregistrement).

![9 · Les actions possibles sur un Data store : ajouter, vérifier, compter, supprimer… On choisit « Add/replace a record »](/formation/captures/mk-10-data-store.webp)

3. Clique sur **Add** pour créer le Data store « Demandes de devis », puis définis sa **structure** : une ligne par colonne, avec son type.

![10 · La structure du Data store : Date de réception, Prénom, Nom, E-mail, Entreprise, Besoin (texte), Budget (nombre) et Statut](/formation/captures/mk-11-structure.webp)

> Pense comme au module 3 : **des noms de colonnes clairs et toujours les mêmes**, et le bon type (un budget en *nombre* pourra être trié et additionné).

## Étape 4 · Le mapping : relier chaque champ

C'est l'étape clé de toute automatisation : dire à Make **quelle donnée va dans quelle colonne**.

1. Clique dans le champ **Prénom** du Data store : un panneau s'ouvre avec les données reçues par le webhook (le module **1**).
2. Clique sur **prénom** : une **pastille rouge** `1. prénom` s'insère. Fais de même pour chaque colonne.

![11 · Le panneau des variables : chaque pastille correspond à un champ reçu par le webhook (module 1), avec la valeur du test à côté](/formation/captures/mk-13-panneau-variables.webp)

3. Pour la **date de réception**, ouvre l'onglet **calendrier** du panneau : clique sur la fonction **formatDate**, insère la variable **now** à l'intérieur, puis tape le format `DD/MM/YYYY HH:mm`.
4. Pour le **statut**, tape simplement le texte `Nouveau` : toutes les demandes arrivent avec ce statut.

![12 · Les champs reliés : la date est calculée par formatDate(now ; DD/MM/YYYY HH:mm), les autres colonnes reçoivent les pastilles du webhook](/formation/captures/mk-14-champs-mappes.webp)

> **Astuce** : ferme le panneau des variables (la croix en haut à droite) avant de cliquer dans le champ suivant. Tu peux aussi taper `{{1.prenom}}` directement : Make le transforme en pastille.

Clique sur **Save** (Sauvegarder) dans le module, puis enregistre le scénario (icône disquette en bas) et donne-lui un nom clair en cliquant sur son titre : « Demande de devis · Formulaire → Data store ».

## Étape 5 · Tester

1. Clique sur **Run once** (Exécuter une fois) : le webhook se met en attente.
2. Envoie une demande depuis ton formulaire.
3. Les modules passent au vert et une **bulle** apparaît au-dessus de chacun : elle indique le nombre d'opérations réalisées.

![13 · Test réussi : coches vertes et bulle « 1 » au-dessus de chaque module](/formation/captures/mk-15-execution.webp)

4. Clique sur la bulle du Data store pour voir **ce qui est entré et ce qui est sorti**.

![14 · Le détail de l'exécution : à gauche, l'enregistrement envoyé au Data store avec la date formatée et le statut « Nouveau » ; à droite, la clé créée. En haut : 1 opération, 1 crédit](/formation/captures/mk-16-resultat.webp)

5. Vérifie le résultat dans **Data stores** (menu de gauche, rubrique *More* si besoin) : la demande est enregistrée.

![15 · Le contenu du Data store : la demande de Camille Durand est bien rangée, colonne par colonne](/formation/captures/mk-21-data-store-contenu.webp)

> **Les crédits** : chaque module exécuté consomme un crédit (on parlait d'« opérations »). L'offre gratuite en inclut un nombre limité chaque mois : un scénario de 2 modules qui tourne 200 fois consomme environ 400 crédits. Vérifie ta consommation dans **Org › Utilisation**.

## Étape 6 · Ajouter un filtre

Un filtre se pose **sur la liaison entre deux modules** : la suite du scénario ne s'exécute que si la condition est remplie. Ici, on n'enregistre que les demandes qui ont une adresse e-mail.

1. Clique sur la **clé à molette** entre les deux modules, puis **Set up a filter**.
2. Donne un nom au filtre : « E-mail renseigné ».
3. Condition : la pastille `1. email`, opérateur **Basic operators › Exists**.

![16 · Le filtre : la condition porte sur le champ e-mail reçu, avec l'opérateur « Exists » (le champ existe et n'est pas vide)](/formation/captures/mk-18-filtre-exists.webp)

Les autres opérateurs utiles : **Equal to** (égal à), **Contains** (contient), **Greater than** (supérieur à) pour les nombres, ou des conditions sur les dates. **Add AND rule** combine plusieurs conditions, **Add OR rule** propose des alternatives. Pour envoyer les demandes vers **plusieurs chemins** (par exemple vidéo d'un côté, photo de l'autre), utilise le module **Router**.

## Étape 7 · Planifier et activer

Clique sur **Schedule settings** (Paramètres de planification) en haut de l'écran.

![17 · Les options de planification : « Immediately » pour un webhook, ou à intervalles réguliers, chaque jour, en semaine, chaque semaine, chaque mois…](/formation/captures/mk-20-planification.webp)

- Avec un **webhook**, garde **Immediately** : le scénario démarre dès qu'une demande arrive.
- Pour une tâche récurrente (la relance hebdomadaire de l'atelier précédent, un rapport du lundi), choisis **Weekly** ou **Daily** et l'heure.

Enfin, bascule l'interrupteur **Inactive → Active** en haut à droite : ton scénario fonctionne désormais tout seul, même ordinateur éteint. L'onglet **History** (historique) garde la trace de chaque exécution, avec les erreurs éventuelles.

## Make ou n8n : lequel choisir ?

| | Make | n8n |
|---|---|---|
| Prise en main | très visuelle, idéale pour débuter | un peu plus technique |
| Hébergement | en ligne (serveurs en Europe disponibles) | en ligne ou sur ton propre serveur |
| Prix | gratuit pour démarrer, puis selon le nombre de crédits | gratuit si tu l'héberges toi-même, sinon abonnement selon le nombre d'exécutions |
| Applications connectées | plusieurs milliers | plusieurs centaines, plus les requêtes HTTP vers n'importe quel outil |
| IA et agents | modules IA, Make AI Agents | étapes IA et agents très complets |

*Repères d'octobre 2026 : vérifie les offres à jour sur les sites des éditeurs.* Le bon choix est souvent **celui que tu vas vraiment ouvrir** : si l'interface de Make te parle davantage, c'est un excellent outil pour démarrer.

## À retenir

- Make et n8n reposent sur **les mêmes notions** : déclencheur, modules, mapping, filtre, planification, historique.
- Le **mapping** (les pastilles) relie chaque donnée reçue à sa destination.
- Un **filtre** se pose sur la liaison entre deux modules ; un **Router** crée plusieurs chemins.
- Chaque module exécuté consomme des **crédits** : surveille ta consommation.
- **Run once** pour tester, puis l'interrupteur **Active** pour mettre en service.

## À toi de jouer (45 minutes)

1. Reproduis ce scénario dans Make avec **ton propre formulaire**.
2. Ajoute un filtre adapté à ton activité (par exemple : budget renseigné, ou besoin égal à « Vidéo »).
3. Envoie 3 demandes de test, dont une sans e-mail, et vérifie dans l'historique que le filtre a bien bloqué la troisième.
4. Note ton scénario dans ton **registre des automatisations**.
